# DIYRuZ_Zintercom: исправленная версия

Обновлённый файл: `DIYRuZ_Zintercom.js`.

## Что исправлено

- Корневой `require('zigbee-herdsman-converters')` заменён прямыми импортами `converters/fromZigbee` и `converters/toZigbee`. Это уменьшает связанность с корневым API; выигрыш во времени на сервере не измерен.
- `state` вынесен в отдельный `toZigbee` с `convertGet` без `convertSet`. GET продолжает читать 0x0050; попытка записи не отправит неопределённый payload.
- Два запроса настройки батареи объединены в один `configureReporting('genPowerCfg', [...])`. В `configure()` теперь четыре последовательные операции вместо пяти: два bind и два configureReporting. Параллельных радиозапросов нет; интервалы, атрибуты и типы сохранены. Поддержку объединённого запроса надо проверить на устройстве.
- После записи `mode`, `once`, `always`, `drop` нет дополнительного read. После успешного завершения write возвращаются сразу все четыре согласованных свойства. Это оптимистическое состояние, не независимое подтверждение исполнения. Отчёты и явные GET по-прежнему обновляют состояние, в том числе при автоматическом сбросе Once прошивкой.
- Недопустимые значения не доходят до Zigbee: исключены NaN, частично числовые строки, дроби и выход за диапазон uint8. Для режима разрешены исходные названия и числовые коды 0–3; для времени — числа и десятичные строки 0–255. Время в публикуемом состоянии теперь всегда число. Для переключателей допустимы строго `ON`/`OFF`.

Сохранены `DIY_Zintercom`, модель, `factory_reset`, обработчик батареи, все exposes, имена, единицы и регистр значений: `Idle/Ring/Talk/Open/Drop`, `Never/Once/Always/Drop`, `ON/OFF`. Семантика OFF тоже исходная: выключение любого из трёх переключателей выбирает Never, даже если прежде активен другой режим. `configureKey` оставлен равным 1; новые настройки отчётов можно явно применить и проверить командой Reconfigure.

## Установка

1. Сохранить резервную копию текущего файла конвертера из каталога `external_converters`.
2. Заменить только файл `DIYRuZ_Zintercom.js` новой версией.
3. Выполнить перезапуск Zigbee2MQTT либо загрузить файл через раздел External converters в интерфейсе.
4. Проверить, что конвертер загрузился без ошибок, и при необходимости выполнить Reconfigure устройства. Режимы проверять отдельно: после записи UI обновляется оптимистически, GET `mode` подтверждает фактическое значение. При реальном звонке проверить автоматический сброс Once и поступление соответствующего отчёта.
5. При необходимости отката вернуть сохранённую резервную копию и выполнить перезапуск. Если новая конфигурация отчётов уже применена, после возврата старой версии также выполнить Reconfigure.

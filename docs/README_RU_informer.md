# PTVO LED Informer — Zigbee2MQTT 2.14.3

Обновлённый файл — `ptvo_led_inform.js`. Совместим с `zigbee-herdsman-converters 26.125.0`, указанной в официальных зависимостях Zigbee2MQTT 2.14.3.

## Почему понадобилась переработка

Ранее использовавшееся короткое определение на основе `modernExtend.light` плюс иконка описывает одну RGB+CCT-лампу и не содержит каналов эффектов, а также отклонялось с ошибкой разрешения ESM-импорта библиотеки.

Устройство Informer (модель `ptvo_led_inform`, прошивка `2022-09-12`) использует endpoint 1–8. На endpoint 1 есть OnOff, LevelControl и ColorControl; на endpoint 2–8 — OnOff и AnalogInput. Возможности цвета `colorCapabilities: 9` включают XY и hue/saturation, но не цветовую температуру. Поэтому итоговая версия восстанавливает функции полного старого определения, а не добавляет общую CCT-лампу.

## Сохранённые функции

| Канал | Назначение | MQTT-свойства |
|---|---|---|
| l1 | Свет, яркость, XY-цвет; RGB/Hue ввод преобразуется стандартным обработчиком | state_l1, brightness_l1, color_l1 |
| l2 | Автоматическая смена эффектов и выбор номера | state_l2, l2 |
| l3–l8 | Быстрые команды эффектов и настройка их номеров | state_l3…state_l8, l3…l8 |

Для переключателей сохранены `ON`, `OFF`, `TOGGLE`. Номера эффектов — целые 0–60 по документации PTVO LED. Сохранены модель, производитель, endpoint l1–l8, `multiEndpoint`, `enhancedHue: false` и встроенная иконка из переданного файла.

Также сохранены служебные команды PTVO `trigger`, `interval`, числовой доступ l1, параметры `switch_type`, `switch_actions`, `link_to_output`, `bind_command`. Новые элементы настройки входов не добавлены в exposes: не все каналы устройства имеют соответствующий кластер. Применять такие команды следует к поддерживающему их endpoint.

## Что изменено

- CommonJS `require`/`module.exports` вместо ESM; использованы прямые пути библиотеки для совместимости с окружением Zigbee2MQTT. Это не означает, что ESM как формат не поддерживается Zigbee2MQTT.
- Обработчики PTVO взяты из текущих `fzLocal`/`tzLocal` в `devices/custom_devices_diy`: старые `fz.ptvo_*`/`tz.ptvo_*` больше не используются.
- Удалённый `fz.ignore_basic_report` заменён локальным обработчиком genBasic.
- Убраны изменения общих объектов библиотеки — локальные обработчики не меняют конвертеры других устройств.
- Исправлен двойной `state` в переключателях: старый код добавлял withState поверх пресета, уже содержащего state.
- Числовые свойства эффектов остались l2…l8, без ошибочных суффиксов l2_l2…l8_l8. Для них добавлены границы 0–60 и шаг 1.
- Неполные отчёты не стирают значения отсутствующих атрибутов. В частности, description без presentValue не записывает NaN/null вместо эффекта.
- Ошибочные значения не отправляются устройству; ошибки записи возвращаются Zigbee2MQTT.
- Файл не выполняет Zigbee-операций при импорте и не добавляет configure с автоматическим обходом восьми каналов.

## Установка

1. Скопировать **только** готовый `ptvo_led_inform.js` в каталог `external_converters` Zigbee2MQTT.
2. Выполнить перезапуск Zigbee2MQTT либо загрузить код через раздел External converters в интерфейсе.
3. Проверить сообщение `Loaded external converter 'ptvo_led_inform.js'` и определение Informer как поддерживаемого устройства.
4. Проверить ON/OFF и яркость/цвет на l1, затем номер и переключатели эффектов на l2–l8. Например, тело MQTT-запроса `zigbee2mqtt/Informer/set`: `{"state_l1":"ON","brightness_l1":153,"color_l1":{"x":0.4,"y":0.3}}`; номер эффекта: `{"l2":7}`; автоматическая смена: `{"state_l2":"ON"}`.
